# Rahim's Spellbook Project

Flag Review checks a contract's wording against the law of a US state or Canadian province. It highlights passages that may be weak, ambiguous, or inconsistent, suggests a clearer rewording for each one, and where a specific statute or code section supports the change, gives a citation.

It is a wording review tool, not legal advice. Citations are generated by the AI model and have not been checked against the statute itself, so verify any citation before relying on it.

## How it works

1. **Choose a jurisdiction.** The user picks a country, then a state or province. The review is framed against that law.
2. **Add the contract.** The user pastes text or uploads a PDF or PNG. Text-based PDFs are read directly on the server. Scanned PDFs and images are read by the AI model.
3. **Review.** The model returns a list of issues. Each one contains the flagged passage, a summary, the reasoning, a suggested rewording, and an optional citation. The server checks every issue against a strict format, and if the model's answer doesn't match, it asks again with the specific error.
4. **Edit and decide.** The contract is editable, and the highlights stay on the right passages as the text changes. Accepting a suggestion replaces the passage. Dismissing leaves the wording as it is.
5. **Download.** When every issue is handled, the updated contract can be downloaded as a PDF.

## Architecture

The browser holds the whole review, the contract text and its issues, and sends it with each request. The server keeps nothing between requests, so contract text is never stored.

```
Browser (React, Vite, Tailwind, shadcn/ui)
   │  contract text + issues, sent with each request
   ▼
Express API (TypeScript)
   ├── Review: prompt, model call, format check, retry with feedback
   ├── Edit sync: re-finds each flagged passage after the text changes
   ├── Accept: applies a suggestion and shifts the remaining highlights
   ├── Upload: reads text-based PDFs locally, scans and images with the model
   └── PDF export: builds the updated contract
   │
   ▼
AI model (Claude by default; Gemini and Groq are also supported)
```

### Design choices

- **No database.** Nothing about a contract is written to disk on the server. The browser is the only place a review lives.
- **The model's output is checked, not trusted.** Every issue must have a passage that exists in the contract, a suggestion, and a citation or an explicit "none." Anything else is rejected and retried with the specific error.
- **Highlights follow the text.** After each edit, every open issue is found again by its quoted text. An issue whose passage was changed is marked resolved.
- **Text PDFs don't need the model.** Their text is read directly, which is fast and free.

## Privacy

Contract text goes only to the AI provider that the server is configured to use. The application does not store it or write it to logs.

## Limitations

- Citations come from the model's own knowledge, not from a statute database.
- The downloaded PDF is plain text. The original fonts, layout, and letterhead are not kept.
- Refreshing the page starts the review over, since nothing is stored on the server.
